---

## 1. 一句话定位

> **zzdzz 自己的写作与思考空间。** 不是内容平台,不是 CMS,不是 AI 聊天工具的宿主——
> 是一个"愿意持续写"的人,把已经写完的东西,放在自己跑的小服务器上。

边界:任何会让"写作本身"变得更难、或让"作者本人"变成内容运营的功能,都暂缓。

---

## 2. 用户与场景

只有两类"人"在用这个产品,先认清楚:

| 角色 | 实际身份 | 关心什么 | 典型动作 |
| --- | --- | --- | --- |
| **作者** | 也就是 zzdzz 本人(可能未来会多一两个共写者) | 写得顺、找得到、改得动、隐私可控 | 写文章 / 改笔记 / 跟 AI 聊选题 / 切可见性 |
| **读者** | 朋友 + 路过的人 + 搜索引擎 | 读得舒服、能搜、能分享 | 浏览 / 搜索 / 收藏 / 评论(未来) |

匿名读者(没登录)能看公开内容,这是默认状态,不要求注册。
登录用户(无论是不是作者)能进个人空间,能写只能自己看的笔记。
只有作者本人有后台与用户管理。

---

## 3. 三大模块

整个产品收敛到三块,**加新东西先看它落不进哪块**:

### 3.1 公开博客(client)

读者看的部分。

- 文章列表 + 标签云 + 分类
- 文章详情 + Markdown 渲染 + 阅读量
- 搜索(标题/摘要/正文)
- 留白多、字体稳、配色克制,不靠动效拉注意力

未来:评论、点赞/收藏、订阅(RSS / 邮件 / Telegram 频道)、归档页、关于页。

### 3.2 个人空间(space)

作者自己看自己写的东西。**对外不暴露。**

- 笔记列表(可按可见性、分类、标签筛)
- 笔记编辑器(双栏预览 / Markdown)
- 个人资料 + 修改密码
- 写作统计(本周写了多少 / 哪类最多)

未来:草稿自动保存、写作日历、回顾邮件(周日发"这周写了 3 篇")。

### 3.3 后台(admin)

作者管理**公开**内容的控制台。比 space 更"对外",比 client 更"权威"。

- 文章 CRUD(含分类、标签、可见性)
- 分类 CRUD
- 用户管理(新增共写者、停用、重置密码)
- AI 对话(选题 / 润色 / 翻译 / 起标题)

未来:RAG 知识库(把自己写过的所有内容喂回去,做"和我聊天"风格的私有助手)。

---

## 4. 横切能力

不属于任何一块、但每块都依赖:

- **可见性三态**:`public` / `private` / `draft`。这是产品的核心约束,不是按钮。
  - 公开:读者可见
  - 仅自己:凭 token 可见,匿名 404
  - 草稿:连作者访问 URL 都 404(防误发链接)
- **AI 接入**:OpenAI 兼容协议,默认 MiniMax-M3,流式 SSE。
- **身份**:单 SPA 内三态切换(client / space / admin),不强制注册。

---

## 5. 不做什么(明确边界)

把不做的事也写下来,免得以后被"加个功能吧"反复推:

- ❌ 多用户社交(关注 / 粉丝 / 通知 / 动态流)—— 这不是博客
- ❌ 富文本所见即所得—— 坚持 Markdown,写作工具的活交给外部
- ❌ 评论审核后台 / 内容审核 —— 单作者博客不需要
- ❌ 数据分析后台(阅读时长、用户画像)—— 知道有读者就够了
- ❌ 移动端 App —— 响应式 web 够用,后端 API 已经为它留好

---

## 6. 路线图(粗)

按"能让写作更舒服"的程度排,不按"听起来酷":

| 阶段 | 目标 | 关键产出 |
| --- | --- | --- |
| **v0.1 (现在)** | 能写、能读、有后台、有 AI | 已交付:MVP + demo |
| **v0.2** | 写作体验打磨 | 标签系统(已原型)、草稿自动保存、写作统计 |
| **v0.3** | 读者体验打磨 | 评论、点赞、订阅、归档 |
| **v0.4** | 私有知识库 | RAG 接入,AI 不再是无记忆的聊天 |
| **v1.0** | 第二位作者 | 共写者流程跑通,权限矩阵写清楚 |

每跨一个版本,都先回到第 1 节那句话问:**这件事让"写"变难了吗?** 如果变难,往后排。

---

## 7. 关键约束(技术 / 运维视角)

产品文档里只列"会反过来影响产品"的:

- 单人维护 → 部署必须一条命令(已有 `deploy/`),数据库备份必须自动
- 隐私优先 → 任何"会发到第三方"的功能(评论、统计)默认关,显式开
- 数据可迁 → 所有内容用 Markdown 落库,可一键导出
- 域名要稳 → 不依赖任何 SaaS 的"短链"或"嵌入"

## 8. 下一步

读完这份文档应该能回答:

- 我现在最该做 v0.2 的哪一项? → **先做草稿自动保存**(降低写作中断成本,比标签更影响写作频次)
- 我能不能跳过 v0.3 直接做 v0.4? → 能,但要先确认写作频次到没到"内容多到需要被自己检索"的程度
- 有人提议"加个评论"怎么办? → 翻到第 5 节,先看是不是边界
