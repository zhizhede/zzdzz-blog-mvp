# v0.3 技术方案:AI 回顾(RAG 知识召回)

> 范围:让 AI 对话能"无感地"召回用户自己写过的内容——用户没在聊天里说过、
> 但在自己文章/公开文章里写过的东西,AI 也能答出来,并给出引用来源。
> 对应 [`doc/product-design.md`](./product-design.md) 中 admin 模块的未来项
> "RAG 知识库(把自己写过的所有内容喂回去,做'和我聊天'风格的私有助手)"。
>
> 本文档面向"动手改代码的自己"。产品决策已定,不再讨论要不要做:
>
> | 决策点 | 结论 |
> | --- | --- |
> | 索引范围 | 公开文章 + 私人笔记,draft 永不入索引,配置留 `index_private` 总开关 |
> | 向量化 | 通用 OpenAI 兼容配置(base_url / api_key / model / dims),不锁供应商 |
> | 交互形态 | **不做独立模式**,所有 AI 对话默认无感携带召回,闲聊时行为不变 |
> | 开放范围 | 所有登录用户,检索按可见性过滤(公开 + 自己的) |
>
> 第一设计目标:**可扩展性**。后续 AI 与博客功能尚未定型,
> 所有"未来可能变"的地方收敛成显式接缝,见 §8。

---

## 0. TL;DR

- **存储**:Postgres 装 pgvector,单表 `ai_chunks`,HNSW 索引。
  表带 `source_type`(预留多内容源)+ 冗余 `owner_id`/`scope`(检索过滤免 join)。
- **向量化**:新增 `EmbeddingClient` 接口 + OpenAI 兼容实现,配置进 `ai.embedding`。
- **接入**:只改 `SendMessage` 一条链路——检索 → 低于阈值不注入 → 注入上下文 →
  首个 SSE 事件推引用来源。embedding 未配置/失败/低分,行为与现状完全一致。
- **同步**:文章 Create/Update 后异步重建该文 chunks;SetVisibility 只 UPDATE
  `scope` 列不重嵌入;autosave 不挂钩(draft 不索引);附 `cmd/embed-backfill` 幂等回填。
- **前端**:AICenter.vue 的 SSE 解析加一个 `obj.sources` 分支,渲染可点引用条。
- 不引任何新依赖,唯一外部要求:**服务器 Postgres 可用 pgvector 扩展**(见 §10 部署)。

---

## 1. 设计原则

1. **无感优先**:召回是现有对话的增强,不是新功能。用户不学任何新东西,
   UI 不加开关(产品决策)。相应地,所有失败路径必须静默降级为现状。
2. **可见性是产品核心约束,检索必须继承**。过滤规则与 `ArticleService`
   现有判权一致(admin 全量 / 作者本人含 private / 老文章 author 为 NULL 仅 admin)。
3. **为没想好的事留接缝,但不为它写代码**。未来功能只允许"填空",
   不允许"返工"——见 §8 对照表。
4. 不破坏 v0.2 的既定原则:单 Postgres、不引新依赖、改动面最小。

## 2. 现状与缺口

| 现状 | 影响 |
| --- | --- |
| AI 上下文只有会话内最近 20 条(`handler/ai.go` SendMessage 步骤 2) | AI 对博客内容零感知,是"裸聊天" |
| README 已预留"建议启用 pgvector 以备未来 RAG 用" | 数据库方向早已明确,本次兑现 |
| `articles` 有 `author_id`(可 NULL)/ `visibility`(public/private/draft)三态 | chunk 表冗余这两列即可在 SQL 里完成判权 |
| SSE 协议是 `data: {"delta"}` / `data: {"error"}` / `data: [DONE]`,前端按 JSON 字段分支 | 新增 `sources` 字段即向后兼容,旧前端自然忽略 |
| embedding 相关配置/代码为零 | 全部新增,无迁移包袱 |

## 3. 数据库变更

文件 `server/migrations/0009_ai_recall.sql`:

```sql
CREATE EXTENSION IF NOT EXISTS vector;

-- 维度建表时定死. 实测 MiniMax embo-01 返回 1536 维(官方文档标注 1024 与实际不符)。
-- 未来换维度 = 新迁移改列类型 + 全量重嵌,backfill 命令即重嵌工具,见 §8。
CREATE TABLE ai_chunks (
  id          BIGSERIAL PRIMARY KEY,
  source_type VARCHAR(16)  NOT NULL DEFAULT 'article',  -- 预留: article / message / ...
  source_id   BIGINT       NOT NULL,                    -- article.id
  owner_id    BIGINT,                    -- 冗余 articles.author_id, NULL = 老文章
  scope       VARCHAR(16)  NOT NULL,    -- public / private;draft 不入索引
  chunk_index INT          NOT NULL,
  heading     VARCHAR(255),              -- 所属小节标题路径, 供引用展示
  content     TEXT         NOT NULL,
  metadata    JSONB,                     -- {title, slug, category, tags, published_at}
  embedding   vector(1536) NOT NULL,
  created_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
  updated_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
  UNIQUE (source_type, source_id, chunk_index)
);

-- 语料量级:几百篇 × 每篇几个 chunk ≈ 数千行, HNSW 足够; 老版本 pgvector(<0.5)退 ivfflat
CREATE INDEX idx_ai_chunks_hnsw   ON ai_chunks USING hnsw (embedding vector_cosine_ops);
CREATE INDEX idx_ai_chunks_scope  ON ai_chunks (scope, owner_id);
CREATE INDEX idx_ai_chunks_source ON ai_chunks (source_type, source_id);
```

设计说明:

- **冗余 `owner_id` / `scope`**:检索过滤不走 JOIN articles。代价是文章改作者/
  改可见性时要同步这两列——改作者一期不支持(现有代码同样不支持),改可见性
  走 `UpdateScope` 轻量路径(§5)。
- **`metadata` 用 JSONB**:引用展示需要标题和链接,不想 JOIN;且未来
  `source_type` 扩展后各来源的元数据形状不同,强列会锁死。
- **删除文章** → handler 现有 Delete 事务后追加 `RemoveArticle`,按
  `(source_type, source_id)` 清理,不依赖外键级联(articles 表未建 FK 约束,保持一致)。

## 4. 配置变更

`config.yaml`(Viper 键沿用小写点分,环境变量 `ZZDZZ_AI_EMBEDDING_*` 自动生效):

```yaml
ai:
  # ...现有 base_url / api_key / model / enabled 不动, 语义就是 chat 配置...
  embedding:
    base_url: ""        # 可与 chat 不同供应商; 空则禁用召回
    api_key: ""
    model: ""           # 如 bge-m3 / embo-01
    dims: 1536          # 启动时校验必须与迁移一致(当前 1536), 不符直接 fail fast
  recall:
    enabled: true       # 总开关, 独立于 embedding 配置存在
    top_k: 5
    min_score: 0.45     # cosine 相似度下限, 低于则不注入任何上下文
    index_private: true # 关闭时删除全部 private chunk 并停止索引私人笔记
```

- `recall.enabled=false` 或 `embedding` 未配置 → 代码路径等价于现状,不报错。
- `index_private` 从 true 翻 false 时,启动时执行一次清理(private chunk 删除),
  反向翻转时由下一次回填/文章更新补齐。

## 5. 后端模块

### 5.1 EmbeddingClient(供应商接缝)

```go
// internal/service/embedding.go
type EmbeddingClient interface {
    Embed(ctx context.Context, texts []string) ([][]float32, error)
}
// 唯一实现: openaiEmbeddingClient, 走 go-openai 的 CreateEmbeddings,
// base_url / api_key / model 全部来自 ai.embedding 配置。
```

未来换本地 ollama、加缓存层、加批量合并,都只动这一个接口的实现。

### 5.2 RecallService(检索与索引)

```go
// internal/service/recall.go
type AccessQuery struct { UserID uint64; IsAdmin bool }   // 未来加 Anonymous bool

func (s *RecallService) Search(ctx context.Context, q AccessQuery, query string, topK int) ([]RecallHit, error)
func (s *RecallService) IndexArticle(ctx context.Context, a *model.Article) error   // 删旧插新, 幂等
func (s *RecallService) RemoveArticle(sourceID uint64) error
func (s *RecallService) UpdateScope(sourceID uint64, scope string) error            // 不重嵌
```

**判权规则收敛在一个函数里**(这是"访客问博客"未来唯一的填空点):

```go
// scopeFilter 返回 SQL 片段与参数, 语义与 ArticleService 判权一致:
//   admin:       全部(scope != 'draft', 表里本来就没有 draft)
//   普通用户:    public + 自己的 private;老文章(owner IS NULL)的 private 仅 admin
// 未来匿名读者: 仅 public —— 只改这里
```

检索 SQL(语料数千行,OR 过滤走 HNSW 扫描后过滤即可,不需要 partition):

```sql
SELECT source_id, heading, content, metadata, 1 - (embedding <=> $1) AS score
FROM ai_chunks
WHERE scope = 'public'
   OR (scope = 'private' AND owner_id = $2)
   OR (scope = 'private' AND owner_id IS NULL AND $3)   -- $3 = is_admin
ORDER BY embedding <=> $1
LIMIT $4;
```

**分块**:按 Markdown 二级/三级标题切,每块目标 500–800 字(按 rune),
无标题的长文按段落硬切。**入向量与入 metadata 的文本都带上下文头**:

```
《文章标题》· 2025-03-02 · 分类/标签
## 小节标题
正文 chunk...
```

时间语义必须进向量——"回顾以前发的东西"这个场景,用户会问
"我什么时候写过 XX",只有正文向量答不出来。

### 5.3 索引同步钩子

| 触发点 | 动作 |
| --- | --- |
| `ArticleService.Create` / `Update` 成功后 | `go IndexArticle`(embedding 在前、删旧插新在后,失败仅记日志不影响保存) |
| `ArticleService.Delete` 成功后 | `RemoveArticle` |
| `ArticleService.SetVisibility` 成功后 | draft→public/private 时 `IndexArticle`(首次入索引);其余 `UpdateScope` 只改过滤列,**不重新嵌入** |
| autosave | **不挂钩**。draft 永不入索引,顺带避免每 8 秒一次的 embedding 调用 |

回填:`server/cmd/embed-backfill`,遍历全量非 draft 文章 → `IndexArticle`,
幂等可重跑,同时也是未来换模型的"全量重嵌"工具。

## 6. 对话链路接入(唯一改动的现有链路)

`SendMessage` 在"步骤 2 加载历史"与"步骤 3 assistant 占位"之间插入:

1. `recall.enabled && embedding 已配置` 才走检索,否则跳过(等价现状);
2. 对**最新一条 user 消息**做 embedding → `Search(AccessQuery{uid, isAdmin}, ...)`(约 +100–300ms);
3. 命中(`score >= min_score`)时,把 chunks 组装成一条 **system 消息**插到历史最前:

   ```
   以下是用户过去写下的相关内容片段,可在回答中自然引用,禁止虚构未出现的内容。
   每段开头标注了出处标题与时间。
   [1] 《标题》(2025-03-02, 私人笔记/公开文章)
   <chunk 内容>
   [2] ...
   ```

4. 在 token 流开始前发一个 SSE 事件:

   ```
   data: {"sources":[{"index":1,"article_id":42,"title":"...","heading":"...","score":0.82}]}
   ```

   前端按 JSON 字段分支,现有解析只认 `error`/`delta`,未知字段自然忽略,向后兼容。

**降级矩阵(全部静默,不向前端报错)**:embedding 调用失败 / 未配置 /
命中为空 / score 全低 → 与现状行为逐字节一致。

一期取舍:sources **不持久化**,历史消息看不到当时的引用。要做再说(可在
assistant 消息加 metadata 列),不阻塞本期。

## 8. 扩展点对照表(本期真正交付的"可扩展性")

| 未来可能要做的事 | 现在预留的接缝 | 到时候要写的代码 |
| --- | --- | --- |
| 编辑器 AI 快捷操作(起标题/摘要) | chat 配置与 openai client 不动 | 新 handler 方法,复用 client |
| AI 对话记录也进回顾(`ai_messages` 入索引) | `source_type` 列 + JSONB metadata | 新增 `IndexMessage`,`source_type='message'`,owner=会话 user,scope=private |
| 访客"问博客"(匿名公开问答) | `AccessQuery` + `scopeFilter` 单点判权 | AccessQuery 加 Anonymous,filter 少两个 OR 分支,外加限流 |
| 回顾邮件 / 那年今日 / 相关文章推荐 | `RecallService.Search` 与 chunk 时间 metadata | 新的调用方,零 schema 变更 |
| 换 embedding 模型 / 维度 | dims 走配置但启动校验;backfill 幂等 | 新迁移改列类型 → backfill 全量重嵌 |
| 共写者规模扩大 | `owner_id` 从第一天就是按用户隔离的 | 无 |
| 检索质量不够(中文分词/混合检索) | 表结构与检索接口不假设纯向量 | 加 tsvector 列 + zhparser,Search 内部混合排序 |

反面对照(明确**不做**的过度设计):不建通用"文档管道"抽象、不做多向量库、
不做 reranker、不给 source_type 写注册表机制——一期只有一种来源,
枚举值够用,接缝留在列上而不是代码里。

---

## 9. 一期边界(明确不做)

- 不做混合检索 / 中文全文分词:语料数千行,纯向量够用,且 zhparser 在宝塔
  Postgres 上不一定装得上。
- 不做 sources 持久化、不做召回效果评测面板、不做 AI 接口限流
  (全部用户是登录用户;访客开放时限流是必做项,已在 §8 接缝备注)。
- draft 不索引——它同时解决了"autosave 高频写库触发重嵌"的问题。

## 10. 实施顺序与部署前提

**部署前提(先确认再动手)**:服务器 Postgres 需能 `CREATE EXTENSION vector`。
宝塔编译安装的 Postgres 多半没有 pgvector;Docker 部署换 `pgvector/pgvector`
镜像或 apt 装 `postgresql-16-pgvector`。装不上扩展则本期不开工(没有合理的
降级替代——应用内存算余弦是备选,但放弃 SQL 判权过滤,不推荐)。

1. 迁移 `0009` + `cmd/embed-backfill`(此时无任何行为变化)
2. `EmbeddingClient` + `RecallService` + 单测(chunk 切分、scopeFilter SQL、降级路径)
3. `SendMessage` 接入 + SSE `sources` 事件
4. AICenter.vue 引用条
5. 回填存量 → 服务器 `curl` 验证 SSE 首事件与降级路径

验证口径:闲聊类问题(命中为空)回复与现状一致;写过的主题能引出旧文且
引用可点;private 笔记只能被作者本人召回;embedding 停配后一切照旧。
