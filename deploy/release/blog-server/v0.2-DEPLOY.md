## 2. 升级步骤 (在宝塔上, 按顺序)

```bash
# 假设 release 包上传到 /tmp/zzdzz-v0.2/
REL=/tmp/zzdzz-v0.2/blog-server
TARGET=/www/wwwroot/blog-server

# 0. 停服务 (宝塔面板 → 项目 → 停止, 或命令行)
#    不要用 kill -9, 让 Gin 优雅退出

# 1. 备份现有 release (回滚用)
mv $TARGET /www/wwwroot/blog-server.bak.$(date +%Y%m%d-%H%M)

# 2. 拷贝新 release 到目标路径
cp -r $REL $TARGET

# 3. 恢复真实配置 (生产环境的密码/密钥, 不在 git 里)
#    注意: 本次 release 里 config/config.production.yaml 是占位符, 不能直接用
#    从 .bak 里把真实配置复制回来:
cp /www/wwwroot/blog-server.bak.*/config/config.production.yaml $TARGET/config/

# 4. 跑 migration 增量 (0007 + 0008)
PGPASSWORD='<你的 pg 密码>' psql \
  -h 127.0.0.1 -p 35432 -U postgres -d zzdzz_blog \
  -v ON_ERROR_STOP=1 \
  -f $TARGET/migrations/0007_article_autosave.sql

PGPASSWORD='<你的 pg 密码>' psql \
  -h 127.0.0.1 -p 35432 -U postgres -d zzdzz_blog \
  -v ON_ERROR_STOP=1 \
  -f $TARGET/migrations/0008_tags.sql

# 两条都是 IF NOT EXISTS, 幂等, 重复跑不会出错

# 5. 替换 JWT secret (如果不是从备份恢复, 占位符在生产环境是公开的)
NEW=$(openssl rand -hex 32)
sed -i "s|REPLACE_WITH_OPENSSL_RAND_HEX_32_OUTPUT|$NEW|" $TARGET/config/config.production.yaml

# 6. 启动后端
chmod +x $TARGET/blog-server $TARGET/draft-cleanup
# 宝塔面板 → 项目 → 启动
# 或命令行:
#   cd $TARGET && ./blog-server

# 7. 同步前端 dist 到 nginx 站点目录 (按 deploy-bt.md §9)
scp -r $TARGET/web/. root@<host>:/www/wwwroot/blog-ui/dist/

# 8. 强刷浏览器 (Ctrl+Shift+R)
```

## 3. 新增: 草稿清理计划任务

`draft-cleanup` 是个独立二进制, 不会自动跑。挂到宝塔计划任务:

- 任务名: `zzdzz-draft-cleanup`
- 执行周期: 每天 04:00
- 脚本内容:

```bash
#!/bin/bash
cd /www/wwwroot/blog-server
./draft-cleanup -days 30 || /usr/bin/logger -t zzdzz "draft-cleanup failed"
```

> 第一次跑先用 `-dry-run` 看会删多少条:
> ```bash
> ./draft-cleanup -days 30 -dry-run
> ```

## 4. 验证清单 (手测, 替代 v0.1 的 4 条)

### 草稿自动保存

1. 打开 `/admin/articles/new`, 输入标题 + 几行正文
2. 等 8~10 秒, 浏览器看 status 栏: `已自动保存 HH:MM:SS`
3. 关闭浏览器, 重新进 `/admin/articles/new` (注意不是同 id)
   - 由于 draft 已建, URL 应该是 `/admin/articles/<id>/edit` —— 8 秒内会触发
   - 文字应在
4. (可选) 数据库查: `SELECT id, last_autosaved_at, updated_at FROM articles WHERE visibility='draft' ORDER BY id DESC LIMIT 1;` —— 应看到 `last_autosaved_at` 一路更新, `updated_at` 不变

### 标签系统

1. 用 admin 登录 → `POST /api/v1/tags {"name": "Vue", "slug": ""}` (slug 自动派生)
2. 编辑任意文章, 在「TAGS」行勾 `#Vue` → 「保存」/「发布」
3. 公开页 `/blog` 应在「标签」行看到 `#Vue 1`
4. 点 `#Vue` → URL 变 `/blog?tag_id=1` → 列表只剩该标签文章
5. 详情页 meta 行应显示 `#Vue` 蓝色 chip, 点回 `/blog?tag_id=1`

### 权限

1. reader 调 `PUT /api/v1/articles/<别人的 draft id>/autosave` → 403
2. reader 调 `POST /api/v1/tags` → 403

### 草稿清理 (干跑)

```bash
cd /www/wwwroot/blog-server
./draft-cleanup -days 30 -dry-run
# 应输出: dry-run: 满足条件的 draft 共 N 条
```

## 5. 回滚

1. 宝塔 → 停止项目
2. `mv $TARGET /www/wwwroot/blog-server.bad.$(date +%Y%m%d-%H%M)`
3. `mv /www/wwwroot/blog-server.bak.<时间戳> $TARGET` 恢复
4. 宝塔 → 启动
5. (可选) DB 回滚: 手动 `ALTER TABLE articles DROP COLUMN last_autosaved_at; DROP TABLE article_tags; DROP TABLE tags;` —— 不会有数据丢失, 这些都是 v0.2 新增的

## 6. 已知限制

- autosave 接口要求 `title` + `content` 都不空, 半空状态不写服务器
- 标签删除是级联, 删前会丢关联 —— 二次确认时 UI 会列受影响文章数
- 没改可见性 / slug 走 autosave 路径, 这些走 Update 接口
- 多标签 AND/OR 过滤 v0.2 不做
